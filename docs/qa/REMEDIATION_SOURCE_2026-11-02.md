## Kontrak API dan migrasi

- Akun existing menerima undangan memakai cookie/Bearer sesi penerima. Password dan display_name dari payload tidak diterapkan. Respons sukses memuat existing_account=true dan assignment_id, tanpa membuat sesi baru. Form memberi tautan login yang kembali ke undangan. Akun baru tetap menerima sesi aktivasi.
- PATCH /api/v1/teaching-events/{id} menerima payload draf dan version. Owner tidak dapat diganti, lifecycle harus DRAFT. Field participant_offering_ids yang dihilangkan mempertahankan peserta; daftar eksplisit merekonsiliasi undangan dengan respons lama yang tetap sah.
- GET /api/v1/tasks?tab=semua menggantikan agregasi enam tab. Participation menerima offering_id opsional untuk kompatibilitas saat kelas hanya punya satu target; lebih dari satu memerlukan pilihan eksplisit.
- GET /api/schedule pada runtime v1 menjadi 410; frontend telah memakai jalur v1. GET /api/tasks hanya mengekspos data LINK aktif yang dipublikasikan, tidak membuka kelas CODE atau arsip.
- Schema version 17 melakukan rebuild tasks pada koneksi khusus dengan FK dipulihkan, transaksi, pelestarian index/trigger, dan foreign_key_check. Tugas/review/materi tetap tersimpan. Approval lama tanpa bukti tidak direkonstruksi; KM perlu mereview ulang proyeksi yang menjadi NOT_REVIEWED.
- SW cache v15 membersihkan cache lama. API tidak disediakan offline. Aset statis tetap dapat dicache dengan pemeriksaan no-store dan URL versi baru.

## Pengujian dan review

- Baseline: go test ./... dan go vet ./... lulus. Empat regresi HTTP awal dijalankan sebelum fix dan gagal pada takeover, scope invitation, bypass blokir, serta perpanjangan sesi.
- Final: `go test ./... -count=1` dan `go vet ./...` lulus. `node --test tests/frontend/remediation.test.cjs` lulus 8 dari 8 tes. Semua berkas Go yang berubah lulus pemeriksaan `gofmt -l`, dan `git diff --check` bersih.
- Tes baru memakai httptest, t.TempDir/database terisolasi, fake sender, dan trigger kegagalan SQLite. Tidak ada test lama dihapus/dilemahkan. Timestamp test retry disesuaikan agar berada pada tanggal lokal reminder yang sama; reminder lama tidak boleh dikirim sebagai informasi hari ini.
- Review standar dan spesifikasi dilakukan terpisah. Finding tambahan tentang builder, starvation, peserta draf, konfirmasi TU, audit deletion, dan stale DELETE sudah ditutup dengan regresi.
- Browser: login PJ berhasil, dashboard terbuka, dan daftar tugas menampilkan tugas fixture dari server httptest dengan akun sintetis dan bot nil. Skenario offline/cache/error diuji melalui mock Node.
- Race detector dicoba: go test -race ./internal/auth ./internal/api ./internal/bot ./internal/notify ./internal/schedule berhenti karena CGO nonaktif; compiler C tidak tersedia. Konfigurasi mesin tidak diubah.

## Batas teknis dan risiko tersisa

Tidak ada pekerjaan implementasi 1–20 yang terhambat. Race detector dan pengiriman WhatsApp provider nyata belum terverifikasi. Tidak ada deployment, commit, push, merge, inspeksi rahasia, atau akses database/sesi produksi; direktori wawancara historis tidak dibaca.

Pengiriman tidak menjamin exactly-once. ID pengiriman stabil didukung adapter WhatsMeow (diverifikasi lewat ctx7 dan kompilasi terhadap versi terpasang). Bila provider sudah menerima tetapi transaksi finalisasi gagal, attempt belum selesai menjadi FAILED dengan DELIVERY_UNCERTAIN setelah reaper; operator harus memeriksa hasil sebelum retry eksplisit. Retry memakai ID stabil yang sama, namun deduplikasi provider tidak diasumsikan terjamin. Pesan yang sudah benar-benar in-flight saat edit/revoke masih dapat tiba; koreksi terbaru tetap durable dan intent lama tidak dijadwalkan ulang otomatis.

Pembatas login memakai serialisasi proses, sesuai arsitektur satu proses aplikasi. Menjalankan beberapa proses penulis terhadap DB yang sama membutuhkan limiter lintas proses; konfigurasi itu tidak ditambahkan.

Pemeriksaan browser mencakup alur PJ di atas. Perbaikan tambahan saat smoke test meliputi sintaks app-pj.js, panel detail/pratinjau yang mengevaluasi data null, dan inisialisasi modal usulan ruangan khusus KM di halaman PJ. Konsol masih mencatat galat Alpine di luar temuan audit pada binding formulir reset sandi dan akses dashboardData.offering saat data awal belum dimuat. Keduanya tidak menghalangi alur PJ yang diuji.
