## 5. Intisari & Implikasi Desain (Key Takeaways)

1. **Pembedaan Jadwal Sementara vs Permanen (*Temporary vs Permanent Reschedule*):**
   - Kebutuhan krusial dari KM: perubahan jadwal kelas pengganti biasanya hanya berlaku satu kali. Sistem harus memiliki mekanisme masa berlaku (*duration/validity period*) dan secara otomatis mengembalikan jadwal ke jadwal reguler semula (*auto-revert*) tanpa perlu diedit ulang secara manual.
2. **Pemberantasan *Chat Clutter* via Web Dashboard:**
   - Masalah utama yang disorot KM adalah riwayat grup WA yang penuh akibat input *command* bot. Web Admin Dashboard adalah solusi mutlak untuk memindahkan seluruh interaksi input, edit, dan konfigurasi ke antarmuka web, sehingga grup WhatsApp murni hanya menerima siaran pesan rapi dari bot.
3. **Panduan Penggunaan Awal (*Onboarding / Empty State Guide*):**
   - Mengingat pengurus kelas dan PJ terus berganti atau memiliki tingkat pemahaman teknis berbeda, sediakan panduan singkat (*walkthrough / user guide*) atau bantuan visual (*tooltip / banner*) di dashboard admin saat pertama kali digunakan.
4. **Manajemen Tanggung Jawab & Hak Akses (*Role Responsibility Delegation*):**
   - KM menyoroti belum adanya pengurus khusus untuk memelihara bot sehingga data sering usang. Sistem dashboard v2.0 perlu mendukung otorisasi peran (KM sebagai pengawas umum, PJ Matkul sebagai penanggung jawab spesifik mata kuliahnya masing-masing).
5. **Integrasi Status Pelaporan Ruangan & Tata Usaha (TU):**
   - Untuk jadwal dadakan, KM bertanggung jawab mencari ruangan kosong dan melaporkannya ke TU. Modul pencarian ruangan kosong akan sangat mempercepat kerja KM dalam menangani jadwal pengganti.
